# Примавтодор — Автодиспетчер

Внутренняя веб-система подачи и ручного согласования заявок на служебные легковые автомобили:
сотрудник подаёт заявку, диспетчер вручную подтверждает её с назначением автомобиля и водителя,
водитель подтверждает получение и отмечает начало и конец рейса. Уведомления — внутри сайта.

Стек: PHP 8.2+ без фреймворков и сторонних пакетов, MySQL/MariaDB (InnoDB, utf8mb4), HTML/CSS
и немного ванильного JS. Node.js не нужен. Целевой хостинг — Beget, домен **paddisp.ru**.

## Что сделано в первой итерации

| Модуль | Состояние |
| --- | --- |
| Миграции БД | все таблицы спецификации + `login_attempts` (`database/migrations`) |
| Вход | логин/пароль, Argon2id, блокировка после 5 неудач за 15 мин, смена временного пароля, сброс пароля администратором |
| Роли | сотрудник, диспетчер, водитель, администратор; права проверяются на сервере в каждом обработчике (`config/permissions.php`) |
| Автопарк | все видят состояние машин (свободна / занята / в ремонте) и поездки на выбранный день; диспетчер меняет статус и ведёт периоды ремонта |
| Заявки | черновик → подана → на рассмотрении → подтверждена / отклонена / отменена → выполнена |
| Подтверждение | только диспетчером, с выбором машины и водителя; защита от двойного бронирования (транзакция + `SELECT … FOR UPDATE` + повторная проверка) |
| Изменение поездки | перенос времени, смена машины или водителя, отмена — через диспетчера, с уведомлениями обеим сторонам |
| Водитель | только свои рейсы; подтверждение получения, начало и завершение рейса (заявка → «выполнена») |
| Уведомления | входящие, счётчик непрочитанных, отметка о прочтении |
| Журнал | все критичные изменения в `audit_log`, просмотр в кабинете диспетчера |

Не входит в эту итерацию: бот MAX (есть только таблицы `max_accounts` и `outbound_messages`),
отчёты, недельный календарь, автоматические напоминания, повторяющиеся заявки.

## Решения по открытым вопросам (по умолчанию из спецификации)

| № | Вопрос | Принято |
| --- | --- | --- |
| Q01 | Заявка на занятую машину | Разрешена: сотрудник видит предупреждение, машина не резервируется, решает диспетчер |
| Q02 | Кто выбирает машину | Сотрудник указывает пожелание, назначает диспетчер |
| Q03 | Водители и машины | Назначаются независимо |
| Q04 | Отмена и перенос подтверждённой поездки | Только через диспетчера; сотрудник может отменить заявку до подтверждения |
| Q05 | Подразделения и видимость | Справочник подразделений, автопарк виден всем |
| Q06 | Бот MAX | Не реализован; только схема БД. Нужны согласование и официальная документация API |
| Q07 | Параметры тарифа Beget | Нужно проверить: версия PHP ≥ 8.2, MySQL, HTTPS, SSH, cron |
| Q08 | Поездки через полночь, повторы | Через полночь — да (поле «Дата окончания»); повторы — во второй версии |
| Q09 | Учётные записи | Создаёт администратор, пользователь меняет временный пароль при первом входе |

Дополнительные правила, принятые в коде:

* интервалы полуоткрытые: поездка 10:00–12:00 не пересекается с 12:00–14:00;
* поездка не длиннее 7 суток; количество пассажиров не больше числа мест в машине;
* статус машины «В ремонте» без дат блокирует любые новые назначения; для планового ремонта
  заводится период, и он блокирует только своё время;
* период ремонта нельзя добавить поверх подтверждённых поездок — сначала их нужно переназначить;
* начатый рейс нельзя переназначить или отменить.

## Структура

```
app/            ядро (Core), бизнес-логика (Services), контроллеры, шаблоны (Views)
bin/            консольные команды: migrate.php, create-user.php, seed-dev.php
config/         настройки приложения, БД и права ролей
database/       migrations/*.sql и демо-данные для разработки (seeds/)
public/         корень сайта: index.php, .htaccess, assets/
storage/        логи и сессии (вне корня сайта)
tests/          тесты (php tests/run.php)
```

## Локальный запуск

```bash
cp .env.example .env            # APP_ENV=development, APP_DEBUG=1, параметры БД
php bin/migrate.php
php bin/seed-dev.php            # демо-пользователи admin, dispatcher, employee, driver… пароль demo-password
php -S 127.0.0.1:8080 -t public public/index.php
```

## Тесты

Нужна отдельная пустая база, в имени которой есть `test` — тесты её полностью очищают.

```bash
TEST_DB_NAME=paddisp_test TEST_DB_USER=… TEST_DB_PASS=… php tests/run.php
```

Тесты покрывают приёмочные критерии спецификации: закрытость внутренних страниц, права ролей,
подачу заявки без резервирования, подтверждение, запрет пересечений по машине и водителю
(включая параллельное подтверждение в двух процессах), ремонты, уведомления, видимость рейсов
водителя и журнал. Они же запускаются в GitHub Actions на MySQL 8.

## Развёртывание на Beget

Ниже — порядок действий; пункты, отмеченные «проверить», зависят от тарифа (вопрос Q07).

1. **Сайт и домен.** В панели Beget → «Сайты» создать сайт `paddisp.ru` и привязать к нему домен
   (DNS уже указывает на Beget: A-запись 87.236.19.78). Включить бесплатный SSL-сертификат для
   `paddisp.ru` и `www.paddisp.ru`.
2. **PHP.** В настройках сайта выбрать PHP 8.2 или новее (проверить доступные версии).
   Нужны расширения `pdo_mysql`, `mbstring`; для Argon2id — `sodium` или сборка с argon2
   (иначе автоматически используется bcrypt).
3. **База данных.** В разделе «MySQL» создать базу и пользователя; имя базы и пароль записать в `.env`.
4. **Код.** По SSH (проверить, что SSH включён):
   ```bash
   cd ~/paddisp.ru
   git clone git@github.com:Aspksa/paddisp.git app     # приватный репозиторий: нужен deploy key
   cd app && cp .env.example .env && nano .env           # APP_ENV=production, APP_DEBUG=0, DB_*
   chmod 600 .env
   ```
   Без SSH — загрузить файлы через файловый менеджер или SFTP в `~/paddisp.ru/app`.
5. **Корень сайта = `public/`.** Конфигурация, `.env`, логи и сессии должны быть вне веб-корня:
   ```bash
   cd ~/paddisp.ru
   mv public_html public_html.orig
   ln -s ~/paddisp.ru/app/public public_html
   ```
   Если символическая ссылка недоступна, можно положить весь проект в `public_html`:
   корневой `.htaccess` перенаправит запросы в `public/` и закроет доступ к скрытым файлам,
   но вариант со ссылкой надёжнее.
6. **Миграции и первый администратор** (CLI-версия PHP должна совпадать с версией сайта — проверить
   командой `php -v`):
   ```bash
   cd ~/paddisp.ru/app
   php bin/migrate.php
   php bin/create-user.php admin "Иванов Иван Иванович" admin   # выведет временный пароль
   ```
   Демо-данные в production не загружаются: `bin/seed-dev.php` отказывается работать при `APP_ENV=production`.
7. **Проверка.** Открыть https://paddisp.ru, войти администратором, сменить пароль, завести
   подразделения, автомобили, диспетчеров, водителей и сотрудников.
8. **Обновления:** `git pull && php bin/migrate.php`.
9. **Резервные копии.** Помимо копий Beget, настроить ежедневный `mysqldump` по cron в каталог вне
   веб-корня и до запуска в работу проверить восстановление из копии.

Безопасность: `.env` и данные не коммитятся (`.gitignore`), SQL только через подготовленные
запросы PDO, CSRF-токены во всех формах, cookie сессии `HttpOnly` + `SameSite=Lax` + `Secure` по
HTTPS, новый идентификатор сессии после входа, заголовки CSP/HSTS/X-Frame-Options.
